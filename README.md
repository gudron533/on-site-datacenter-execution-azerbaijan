## Execution model (core principles)

- **Strict scope**: work only within confirmed scope and procedures
- **No improvisation**: no “creative fixes” that introduce hidden risk
- **Single accountability**: one on-site engineer responsible end-to-end
- **Evidence**: timestamped photo/video evidence when required
- **Clear reporting**: structured updates suitable for enterprise ticketing systems

See: [SOP.md](./SOP.md)

## Quick start (how to run an engagement)

1. Share scope + SOP/checklist (or confirm you want mine as a baseline)
2. Confirm access method (escorted / pre-approved / badge / visitor)
3. Provide asset details (rack/position, serials, parts list, ports, labels)
4. Define reporting method (ticketing system, email, chat, call bridge)
5. Execute on-site and report with evidence as required
